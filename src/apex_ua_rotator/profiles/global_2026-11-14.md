# Global browser profile snapshot — 2026-11-14

`global_2026-11-14.json` is the default weighted profile distributed with Apex UA Rotator since 1.4.0. It models worldwide browser traffic as of 14 November 2026. Earlier snapshots stay bundled unchanged, so earlier results can be reproduced.

## What changed since 2026-07-31

- **Current releases.** Chrome 156 to 158, Edge 156 and 157, Firefox 158 to 160, Opera 139 and 140, Safari 26.6 to 27.2 on macOS, Chrome for iOS 157 and 158, and Firefox for iOS 159 and 160. Safari on iPhone and iPad follows the measured iOS versions, 18.6 to 27.2.
- **The frozen iOS token is now `18_7`.** Safari on iOS and iPadOS 26 and 27 reports the frozen OS token `18_7` with the real Safari version, for example `iPhone OS 18_7 … Version/26.6.1`. The July snapshot used `18_6`, the value Safari 26.0 sent. useragents.me's most-common tables show `18_7` on every Safari 26.4 to 27.2 string they list.
- **Patch releases.** Safari's `Version/` token can carry a patch release (`26.6.1`, `27.0.1`). The profile lint now accepts that format.
- **Chrome for iOS sends the real iOS version.** Chrome for iOS builds its own OS token from the device's iOS version, as `major_minor_patch` (`iPhone OS 26_6_1`, `iPad; CPU OS 18_7_0`); it does not use Safari's frozen token. The July snapshot gave Chrome for iOS Safari's two-part token. Chrome for iOS now follows Safari's modeled iOS distribution with the real token, so the profile has 85 entries.
- **Fewer families.** Samsung Internet, Opera for Android, Edge for Android and Chrome on ChromeOS are left out. See Exclusions.

## Snapshot properties

- 85 unique User-Agent strings
- raw weights totaling exactly 100 (six decimals)
- entries ordered from highest to lowest weight
- desktop, mobile, and tablet coverage
- dated metadata and a versioned JSON schema

## Modeling approach

The matrix is a pragmatic global model rather than a census.

1. **Platforms.** StatCounter's platform shares weight desktop, mobile, and tablet.
2. **Families.** Within each platform, the browser-family shares are those StatCounter measured, renormalized over the families included here.
   - On mobile and tablet, StatCounter's version tables measure Chrome on Android and Chrome on iOS separately.
   - Firefox's mobile share is split between Android and iOS in the July 2026 model's proportions.
3. **Desktop browsers by OS.** No public source gives this table at full fidelity, so the July 2026 model's table is the seed.
   - Iterative proportional fitting then fits it to both October marginals, the browser families and the OSes. It matches Windows, macOS and Linux exactly.
   - Structural zeros stay zero: Safari appears only on macOS.
   - Windows 7 takes its measured share of all Windows traffic (0.43%), all of it on Chrome 109, its final release for Windows 7.
4. **Versions.** Each family's newest, current and previous releases share it in the July 2026 model's release-role proportions. These are a modeled estimate:

   | Family | Newest | Current | Previous |
   |---|---|---|---|
   | Chrome | 10% | 75% | 15% |
   | Edge | 3% | 92% | 5% |
   | Firefox | 25% | 65% | 10% |
   | Opera | — | 80% | 20% |
   | Safari on macOS | 20% | 65% | 15% (retained) |
   | Chrome for iOS | 40% | 60% | — |
   | Firefox for Android | 35% | 65% | — |
   | Firefox for iOS | 60% | 40% | — |

   A role a platform lacks is dropped, and the rest renormalized. Chrome on Linux has no 158 yet, and Edge has no newer release than 157.
5. **iOS versions.** Safari on iPhone and iPad follows StatCounter's iOS version table.
   - useragents.me's observed frequencies split the iOS 26.6 bucket between 26.6.1 and 26.6, and the iOS 27 and 27.0 buckets between 27.0.1 and 27.2.
   - iOS 18.7 and 18.6 devices report their own OS token.
   - Only the six buckets in StatCounter's table are modeled. The remaining 18.63% of iOS traffic, spread over smaller versions such as 26.3, 26.4 and 16.7, is renormalized away. useragents.me's 26.4 figure is cited only as evidence of the frozen token.
6. **Chrome for iOS.** Chrome's share on iPhone and iPad follows the same iOS buckets as Safari, with the real `major_minor_patch` token. The patch level is the Safari release on each bucket: `Version/26.6.1` gives `26_6_1`, and `Version/26.6` gives `26_6_0`. This is a modeled estimate. Safari's `Version/` can omit an iOS patch release (traffic shows `iPad; CPU OS 17_5_1 … Version/17.5`), and a device on such a release sends a different patch number.
7. **Android versions.** Chrome on Android sends the frozen `Android 10; K` token. Firefox for Android sends the device's real Android version, so its entries use Android 16, the most common version.

Every Chromium-based entry uses the reduced User-Agent format: `<major>.0.0.0` versions and the frozen platform tokens. Chrome on iOS (`CriOS`) is the exception: it reports full versions and the real iOS version.

## Exclusions

These families have measured shares but no verified current string, so they are left out:

- **Samsung Internet.** Version 30.0 is measured (mobile 2.61), but its Chromium base is not published on any reachable page, so the `Chrome/` token cannot be stated.
- **Opera for Android.** Opera for Android 102 is current, but its Chromium base is not published.
- **Edge for Android.** The current version is not published on a reachable release page.
- **Chrome on ChromeOS.** The current ChromeOS Chrome version could not be retrieved (the ChromeOS stable post of 2026-11-13 gave no version in its text).
- **Others.** Brave, UC Browser, the Android stock browser, and the families outside StatCounter's top six.

Excluding a family removes its share, and the remaining shares are renormalized within the platform. On mobile this lowers Android to 70.6% of the modeled traffic, against 72.4% measured, because the excluded families are Android browsers.

## Maintenance

Treat the file as replaceable data, not permanent application logic. Browser releases and traffic distributions change continuously; the `as_of` date says how current the model is. Keep dated files for reproducibility, and publish a new dated profile or a numbered revision rather than silently rewriting an old snapshot.

## Fingerprint boundary

A User-Agent header is only one part of an HTTP or browser identity. This profile does not align Client Hints, TLS behavior, HTTP/2 settings, JavaScript-visible properties, viewport, locale, cookies, proxy location, or request pacing.
